# Address review

Take the review a pull request received and implement what the reviewers asked for, on the PR's own branch.

## Which PR

- A PR number, if given.
- Otherwise the current branch's PR: `gh pr view --repo anton-bannykh/ai-workshop-start --json number -q .number`.

## Before you start

Mark that you started working - put a rocket emoji on the review comment.

## Collect the review

Everything reviewers said, in one query: reviews, inline threads (with whether they are resolved), and the conversation.

```sh
gh api graphql -F owner=anton-bannykh -F repo=ai-workshop-start -F number=<number> -f query='
query($owner: String!, $repo: String!, $number: Int!) {
  repository(owner: $owner, name: $repo) {
    pullRequest(number: $number) {
      headRefName
      reviews(first: 100) { nodes { author { login __typename } state body submittedAt url } }
      reviewThreads(first: 100) { nodes { id isResolved isOutdated path line
        comments(first: 50) { nodes { databaseId author { login __typename } body createdAt url } } } }
      comments(first: 100) { nodes { author { login __typename } body createdAt url } }
    }
  }
}'
```

## Ignore

- **Automated reviewers:** author `__typename` is `Bot`, or the login is `jetbrains-air` / `jetbrains-air[bot]`, or ends in `[bot]`.
- **Air automations and other generated reviews, whoever posted them:** a comment that reads as tool output, not a person, such as the
  `review` skill's `**Summary** … **Pros** … **Cons** … **Verdict**` format, or a "Generated by" / Air footer.
- **Already handled:** resolved threads, and requests a later commit or reply on the PR already addressed.
- **Nothing to do:** approvals and comments with no request (thanks, +1, questions already answered).

A person quoting or endorsing a bot's suggestion ("please do what Air suggests") is a human request: implement it.
If nothing is left after filtering, say so, list what was ignored and why, and stop.

## Implement

1. `gh pr checkout <number> --repo anton-bannykh/ai-workshop-start`; `git pull` so the branch is current.
2. List the requests, one line each with its link, and make each change. Follow [AGENTS.md](../../../AGENTS.md):
   update [spec/](../../../spec/) with the code, and an integration test for every new or changed case.
3. A request that is unclear, contradicts the spec, or that you think is wrong: don't guess. Leave it, and ask the user
   with your reasoning.
4. Double-check: re-read the whole diff against each request and the spec, then run `npm run typecheck` and `npm test`
   (and `npm run test:e2e` if the scan of GitHub changed). Everything must pass.
5. Commit with a message that says what changed in response to the review, and push to the PR's branch. Don't open a
   new PR.
6. Wait for CI: `gh pr checks <number> --repo anton-bannykh/ai-workshop-start --watch`. It must be green.

## Reply

On each request you addressed, reply briefly: what changed and the commit. An inline thread:
`gh api repos/anton-bannykh/ai-workshop-start/pulls/<number>/comments/<databaseId>/replies -f body='…'`;
a review or a conversation comment: `gh pr comment <number> --repo anton-bannykh/ai-workshop-start --body '…'`.
Leave resolving threads to the reviewer.

Then record a demo of the change with the [record-demo](../record-demo/SKILL.md) skill and post it in a PR
comment: what the reviewers asked for, working.

## Report

To the user: what was implemented (with links), what was ignored and why, and anything left open for them to decide.
